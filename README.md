# gps_algorithm
#Этап 0: Подготовка (Инициализация GeoMatcher)
Преобразование данных: Алгоритм получает на вход "сырые" координаты объектов в виде прямоугольников ([x1, y1, x2, y2]). Первым делом он вычисляет центральные точки для каждого прямоугольника как на карте, так и на фото. Это упрощает все последующие расчеты, сводя задачу к работе с точками, а не с областями.

Построение графов: Для обоих наборов точек (карта и фото) строится полностью связанный граф. Это означает, что каждая точка считается соединенной со всеми остальными. Одновременно с этим рассчитываются и сохраняются (кэшируются) расстояния между всеми парами точек. Это делается один раз при инициализации для ускорения дальнейших вычислений.

#Этап 1: Поиск эталона на фото
Когда запускается основной метод find_best_match, он начинает с анализа фотографии, чтобы получить "образец" для поиска.

Определение ключевых точек: Алгоритм должен знать три вещи:

  "Якорь" на карте: Точка, которая точно известна.

  "Якорь" на фото: Та же самая точка, но на фотографии.

  "Цель" на фото: Объект на фото, который мы хотим найти на карте.

  Построение эталонного маршрута: Используя граф фотографии, алгоритм находит кратчайший путь (по количеству рёбер) между "якорем" и "целью" на фото. Для этого используется поиск в ширину (BFS). Этот путь (последовательность точек), его общая длина и количество "шагов" (рёбер) становятся эталоном, с которым будут   сравниваться все возможные маршруты на карте.

#Этап 2: Поиск всех кандидатов на карте
  Теперь, имея эталон, алгоритм начинает масштабный поиск похожих структур на карте.

  Перебор потенциальных целей: Алгоритм перебирает каждую точку на карте (кроме якоря) и временно считает её возможным соответствием искомой цели.

  Поиск всех путей: Для каждого такого "кандидата" алгоритм ищет все возможные пути от него до якоря на карте. Для этого используется поиск в глубину (DFS).

  Умное ограничение (фильтр "сектора обзора"): Чтобы не искать совершенно нелогичные, зигзагообразные пути, поиск ограничен "сектором обзора" (_is_in_sector). На каждом шаге построения пути следующая точка должна находиться примерно в направлении конечной цели (якоря). Это резко сокращает количество бессмысленных комбинаций.

  В результате этого этапа мы получаем очень большой список всех теоретически возможных маршрутов на карте.

#Этап 3: Фильтрация и вычисление критериев
  Полученный список кандидатов слишком велик и содержит много "мусора". Начинается процесс отсева и оценки.

  Фильтр по количеству рёбер: Это самый важный и жёсткий фильтр. Алгоритм отбрасывает все маршруты на карте, у которых количество "шагов" (рёбер) не совпадает с количеством шагов в эталонном маршруте с фото. Если на фото путь от якоря до цели занял 2 шага, то на карте рассматриваются только маршруты из 2 шагов.

  Вычисление критериев для TOPSIS: Для каждого маршрута-кандидата, прошедшего фильтрацию, вычисляются два ключевых показателя "похожести" на эталон:

  Критерий 1 (Соотношение длин): Отношение общей длины маршрута-кандидата на карте к длине эталонного маршрута на фото. Идеальное значение — 1.0 (масштаб полностью сохранён).

  Критерий 2 (Схожесть формы): Этот критерий сложнее. Он проверяет, сохраняются ли внутренние пропорции маршрута. Например, если эталонный маршрут состоит из двух отрезков длиной 10 и 20 (соотношение 1:2), то хороший кандидат на карте будет иметь отрезки, скажем, 15 и 30 (тоже 1:2), а не 25 и 20. Этот критерий вычисляется как среднее отклонение пропорций каждого ребра от общей пропорции маршрута. Идеальное значение — 0.0.

#Этап 4: Принятие решения (TOPSIS)
  В итоге у нас есть короткий список лучших кандидатов, и для каждого из них — два числа, описывающих его "качество".

  Поиск ближайшего к идеалу: Метод run_topsis (в данном коде это упрощённая реализация) ищет кандидата, который находится "ближе всего" к идеальной точке. Идеальная точка — это [Соотношение длин = 1, Схожесть формы = 0].

  Выбор победителя: Алгоритм просто вычисляет суммарное отклонение от идеала для каждого кандидата (|Критерий_1 - 1| + Критерий_2). Кандидат с минимальной суммой отклонений объявляется победителем.

#Возможные изменения:

1) Этап 2: Добавление дополнительных критериев для повышения точности метода TOPSIS.
2) Этап 3: Улучшение фильтра и добавление возможности прогнозирования маршрута на основе скорости и высоты полета, что сокращает количество альтернатив для метода TOPSIS.
3) Общие изменения: Количество и тип маршрутов на исходной карте можно просчитывать заранее, что упростит будущие расчеты.
